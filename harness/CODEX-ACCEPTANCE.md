# Standalone acceptance

The earlier vendor-runtime checklist is retired with that architecture.
Current independent acceptance targets are documented in
[STANDALONE-ARCHITECTURE.md](STANDALONE-ARCHITECTURE.md).

Native filesystem/process effects and model calls are checked with temporary workspaces
and scripted inference. These are offline integration tests, not live provider checks.
No real login, provider credentials, paid inference or external deployment is performed.

Official sign-in and search-only integration have separate account/preview requirements;
see [provider documentation](standalone-provider-auth.md).

## Authentication review references

The current official [registration documentation](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)
explicitly supports open-source dynamic registration with the application's actual name,
a stable host identifier, a subsequently issued client ID, and user authorization.
The [inference documentation](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)
specifies the public `https://api.openai.com/v1/responses` endpoint, OAuth bearer tokens,
`store:false` and `stream:true`. This supports the implemented flow; it does not establish
that any particular account is entitled or that a mocked login is a successful real login.
The [MCP cancellation specification](https://modelcontextprotocol.io/specification/2025-06-18/basic/utilities/cancellation)
allows receivers to ignore cancellation and requires clients not to cancel initialization.
The client exposes cancellation only for tool requests and ignores their late responses.

The independent security review found no credential serialization or raw token logging in
the reviewed optional auth module. Tokens, refresh state and authorization attempts remain
private and volatile; official token/JWKS requests refuse redirects and have bounded responses.
No cookies, official-client impersonation or vendor-private backend endpoint is used.

## Extended boundary acceptance

New evidence separates offline inference/desktop fixtures from mandatory Windows kernel checks. Encrypted Responses items survive SQLite close/reopen in order, account/model mismatch fails closed by default, explicit model selection records any incompatible-state reset, and opaque-state compaction refuses silent loss. Public DTOs/events exclude encrypted replay state.

The production ChatGPT image resolver requires exact current run/session/model/account/root/desktop generation plus canonical main-step share scope. Human consent names the captured monitor and exact destination, expiry and use budget; pixels are volatile and never written to conversation history. Authorization is rechecked immediately before transport after token refresh. Synthetic screenshots and browser UI fixtures establish boundaries, not live PC/provider acceptance.

Windows native filesystem compile, temporary filesystem and ancestry-race fixtures, plus zero-network AppContainer/JobObject outsider-read/cancel/timeout fixtures, are mandatory on Windows CI. Linux skips those tests honestly. Fixed diagnostics are the first Windows process milestone; npm project scripts, broader Git and managed worktrees remain unsupported on Windows at this checkpoint.

Managed worktree fixtures use actual temporary Git repositories through an injected TEST runner; production uses the required namespace sandbox and never falls back to host execution. Private-journal ownership, exact immutable consent, unknown/preexisting-tree rejection, bounded checkout and no-force removal are tested. Subsequent live Linux acceptance now uses the production namespace runner; see the checkpoint below.

## Personal assistant authorization

`/assistant` is the local user control surface; its own conversation opens in `/agent`. Existing chats are denied by default. Listing titles does not grant content access. Only user HTTP actions with CSRF protection and explicit connection confirmation can connect chats. Models receive six scoped list/read/status/create/delegate/control tools; they cannot grant or reconnect access. Child chats inherit only an explicit subset of current graph permissions and their originating run's frozen model/executor tool restrictions. Delegation is limited to explicitly created children, one generation and four tasks per originating user turn; ordinary connected chats support reading, bounded native-turn status and exact interruption of their own turns under current read/control grants. Turns owned by another assistant graph are refused.

Graph mutations atomically persist grant changes, a new epoch, metadata-only audit records and context floors. Pending work receives synchronous cancellation; model/tool completion and queued persistence check the original epoch again. Future assistant history and reads exclude messages preceding the committed floor. Project-wide goals, memory and summaries are excluded from assistant-bound context, and oversized assistant context fails closed. Existing visible outputs remain stored; this is future-access revocation, not retroactive forgetting. Reconnecting requires another explicit user action and does not restore removed child permissions automatically.

Scoped assistant children offer coding filesystem tools, approved mutations, fixed sandboxed processes and Git under inherited mutation consent and frozen model/executor scope intersection. Runtime SQLite state and sidecars are excluded from direct reads/writes, staged Git paths and process snapshots. MCP/plugin, browser, desktop and analysis-subagent tools remain withheld from assistant-bound execution. Normal coding chats retain their separately approved capabilities. Resume of assistant runs without a current frozen native policy fails closed after restart; starting a fresh authorized turn remains supported.

Security regressions use actual disk SQLite close/reopen and production tool adapters. HTTP consent checks run against a real offline daemon. Pending inference/tool and prepared-turn races use scripted models and trusted fixture hooks, including revocation at instructions, compilation, prompt commit and run commit. Browser UI checks include production Next with a real isolated offline daemon: explicit connection, exact child subset, backend disconnect, reload and mobile layout passed. These are not live provider tests. An independent Astra high-reasoning reviewer found child-authority, promotion and atomicity bugs before release; regression fixes are included, without claiming a complete product security audit.

Personal-assistant checkpoint local acceptance: **239 files / 2011 tests passed**, with eleven Linux platform skips; full typecheck, lint, format, production build, plugin smoke and runtime/web startup passed. Unchanged performance guards passed at 290.565 ms startup and 97,857,536 bytes idle RSS; dependencies remain ten (nine workspace, one external). A subsequent metadata-title fix passed the seven real HTTP/executor integration tests and runtime typecheck. Windows native process acceptance remains pending; the preceding `aa9b237` Windows run failed two kernel process fixtures, so broader Windows project scripts stay unavailable.
